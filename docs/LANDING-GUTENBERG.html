为什么选择 Publii-CN

做内容站，绕不开一个取舍：WordPress 好用但要维护服务器和数据库，Hugo、Hexo 这类静态生成器快却要面对命令行和主题魔改。对只想安静写文章的人来说，两端都不太舒服。

Publii 是桌面端的静态 CMS：软件装在本地，可视化写文章、配主题，点一下生成就得到一套纯 HTML 文件，上传到服务器或代码仓库即可。没有 PHP、没有数据库，离线也能写，天然规避了数据库注入和大量插件漏洞风险。

Publii-CN 在官方版本之上做了面向中文用户的增强——不止是汉化，而是把分类体系、主题、SEO、排序、摘要等中文场景从头梳理了一遍，并修复了若干真实会踩的坑。

想要 CMS 的可视化省心，又想要静态站点的安全与速度，还不想被英文和命令行劝退——这是 Publii-CN 要解决的问题。

核心功能特色

完整简体中文界面

2085 条翻译键与英文包一一对应，打开即是简体中文。新装默认中文，老配置自动迁移一次且不覆盖用户手动选择。

独立分类栏目体系

官方版只有标签，本分支新增 WordPress 式分类：分类归档页、分类列表页、菜单链接与独立分类 SEO 一应俱全。

两款中文主题

内置企业官网主题 china-corporate 与资讯博客主题 china-news，中文优先字体栈、响应式布局，切换即可用。

中文排版与 SEO 优化

拼音排序、中文摘要按字数截断、拼音 slug、og:locale 与 lang="zh-CN"，让中文站点从排版到搜索都更规范。

GitHub 首次部署修复

空仓库或分支不存在时自动创建引用并提交首个版本，解决了官方流程在新建仓库上推送失败的问题。

WordPress 风格后台

内置经典深色侧边栏与蓝色主色的 WordPress 风格外观，在应用设置中一键切换，降低上手门槛。

两款中文主题怎么选

主题决定站点的第一印象。Publii-CN 内置的两款主题分别面向企业与内容创作者，均针对中文排版做过适配。

两款主题都使用中文优先字体栈，标题行高、断行规则、摘要显示按中文习惯调整，并输出规范的 lang="zh-CN" 与 og:locale="zh_CN"，对搜索引擎与社交分享更友好。

中文优化细节

中文与英文的排版差异很大，这些细节往往是"能用"和"好用"的分界线：

  • 拼音排序：文章、标签、作者、分类、站点名按 zh-Hans-CN 拼音顺序排列，而不是不可读的 Unicode 码位。
  • 拼音网址：中文标题自动生成拼音 slug，例如"新闻"生成 xin-wen，避免冗长的中文编码 URL。
  • 摘要按字数截断：官方版按空格分词，中文段落没有空格导致摘要失效；本分支改为按字数截取并补省略号。
  • 中文标点分隔："你好，世界"不再错误粘连为 ni-haoshi-jie，而是正确生成 ni-hao-shi-jie。
  • 中文字体回退：选择西文字体时自动附加苹方、微软雅黑、思源黑体作为中文回退，避免中文退化成默认宋体。

下载与快速开始

Publii-CN 完全免费，没有功能或站点数量限制。Windows 用户可直接下载安装包，覆盖安装不会丢失站点数据。

  1. 下载安装包并完成安装。
  2. 启动应用，界面默认为简体中文，新建一个站点。
  3. 在网站设置中选择 china-corporate 或 china-news 主题。
  4. 用右侧面板添加分类，撰写文章并生成本地站点。
  5. 在服务器设置中配置 GitHub Pages，一键上传静态文件。

常见问题

Publii-CN 是免费的吗？

完全免费，遵循 GPLv3 协议开源，源码与安装包都可自由获取、修改和再分发，没有功能或站点数量限制。

它和官方 Publii 是什么关系？

它是社区二次开发版本，并非官方发布。项目基于 GetPublii/Publii 修改，按 GPLv3 要求保留修改声明，不使用上游商标或背书。

支持哪些操作系统？

目前提供 Windows 安装包；macOS 与 Linux 暂无预编译版本，可按项目 README 的源码构建步骤自行打包。

部署到 GitHub 需要哪些权限？

建议使用 GitHub Pages 协议，Token 需勾选 repo 权限；若上传内容包含 .github/workflows/ 下的文件，还需勾选 workflow 权限。空仓库首次部署已获支持。

升级会丢失站点数据吗？

不会。站点数据独立存放在"文档\Publii\"目录，覆盖安装不会丢失。
