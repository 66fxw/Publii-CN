我先把话放这儿：小站真的还需要 WordPress 吗？

WordPress 对新手友好、生态成熟，这点没得黑。但问题也很现实：服务器要维护、数据库要备份、插件要更新，隔三差五还得应付安全漏洞——闪核网之前就报道过好几次 CVE，动不动 CVSS 9.8。

对于一个不折腾交互、只发内容的小站来说，这些成本纯属白交。

那换静态站点生成器？Hugo、Hexo、Jekyll 确实快、确实安全，但门槛也真不低：命令行、YAML、Git、主题魔改……不少人卡在第一步就放弃了。

有没有一种东西，既有 WordPress 那种可视化后台的省心，又能产出纯静态文件？还真有，今天这篇就帮大家掰扯明白。

Publii 是一个桌面端 CMS：软件装在你电脑上，可视化写文章、配主题，点一下「生成」就吐出一套纯 HTML 静态文件，往服务器或 GitHub 一丢就完事。没有 PHP、没有数据库，离线也能写。

Publii-CN 是什么

项目特色：不只是汉化，是把中文场景从头捋了一遍

🇨🇳 全中文界面

2085 条翻译键与英文包一一对应，打开就是简体中文。老配置自动迁移一次，不覆盖手动选择。

📂 独立分类栏目

官方版只有标签，本分支补上 WordPress 式分类：归档页、分类列表、菜单链接、分类 SEO 一套齐全。

🎨 两款中文主题

企业官网 china-corporate 与资讯博客 china-news，中文优先字体栈，响应式，开箱能看。

🔤 中文排版优化

拼音排序、中文摘要按字数截断、分类拼音 slug、中文标点不粘连，标题行高与断行也按中文调过。

🚀 GitHub 部署修复

空仓库首次推送 404 失败？自动创建分支引用。主题名带空格导致渲染崩溃？按真实目录名处理。

🎛️ WordPress 风格后台

内置经典深色侧边栏 + 蓝色主色的 WordPress 风格外观，在「应用设置 → 界面风格」一键切换。

两款主题，怎么选？

两款都用了中文优先字体栈，行高、断行、摘要按中文习惯调过，还带 lang="zh-CN" 和 og:locale="zh_CN"，SEO 细节也照顾到了。

中文细节，这块最容易被忽略

  • 文章、标签、作者、分类、站点名按 zh-Hans-CN 拼音顺序排序，不再是乱码一样的码位序。
  • 中文标题自动生成拼音网址（「新闻」→ xin-wen），不会变成一长串中文编码。
  • 摘要按字数截断——官方版按空格分词，中文一整段没空格导致摘要要么全出要么没有，这里修好了。
  • 「你好，世界」不再粘成 ni-haoshi-jie，正确切成 ni-hao-shi-jie。
  • 默认字体栈补齐苹方 / 微软雅黑 / 思源黑体；选西文字体时自动附中文 fallback。

常见问题

它是免费的吗？有什么限制？

完全免费、GPLv3 开源，源码和安装包都可自由获取、修改与再分发，没有功能或站点数量限制。

和官方 Publii 是什么关系？

本项目是社区二次开发版本，非 Publii 官方发布，基于 GetPublii/Publii（版权归 TidyCustoms，GPLv3）修改，按协议要求保留了修改声明，不使用其商标或背书。

支持哪些操作系统？

目前提供 Windows 安装包（约 139MB）。macOS / Linux 尚未提供预编译版本，可按项目 README 的源码构建步骤自行打包。

部署到 GitHub 需要注意什么？

建议用软件里的 GitHub Pages 协议（走 API，比 Git 协议在复杂网络下更稳）。Token 需勾选 repo 权限；若上传内容含 .github/workflows/ 下的文件，还要勾 workflow 权限。空仓库首次部署已支持。

升级会丢站点数据吗？

不会。站点数据独立存放在「文档\Publii\」目录，覆盖安装不会丢失。

静态站点这两年并不缺工具，但缺的是「中文用户拿来就能顺手用」的工具。Publii-CN 干的就是这件笨功夫：把汉化做全、把中文排版理顺、把分类和 SEO 补齐，再把几个真实会踩的坑填掉。
